# Shield Security Journal - CWE-209 Error Sanitization in Shiny Breeding Store

**Date:** 2026-11-01

## Context & Vulnerability (CWE-209)
During a security audit of error logging patterns across state management stores, an unsanitized error logging vector was detected in `src/features/shiny-breeding/store.ts`. The error handler in `loadMetadataForSpecies` logged the raw caught error directly:
`console.error('Failed to load metadata for shiny breeding store', e);`

Passing raw error objects to `console.error` introduces a CWE-209 (Generation of Error Message Containing Sensitive Information) vulnerability. Raw error objects can leak internal system paths, IndexedDB stack traces, database schema details, or underlying storage failure diagnostics into client logs.

## Architectural Constraints & Solution
To eliminate sensitive information leakage:
1. Checked whether the caught exception is an instance of `Error` (`e instanceof Error ? e.message : 'Unknown error'`).
2. Logged only the sanitized error message string rather than the full error object.
3. Added unit tests in `src/features/shiny-breeding/__tests__/store.test.ts` to assert that errors are caught gracefully and never pass raw error objects or non-Error payloads into logging routines.

## Long-term Rules & Patterns
- **Strict Error Redaction:** In any async state fetching routine (Zustand stores, React context, hooks), never pass caught error objects directly to console methods (`console.error`, `console.warn`). Always redact or extract `.message` with a generic fallback.
- **Supply-Chain Integrity:** Transitive dependency vulnerabilities found via `pnpm audit` in workspaces should be monitored and patched via `pnpm-workspace.yaml` overrides or updates when upstream patches become available.

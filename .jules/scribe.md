# Scribe Journal

*   **Gen 3 Save Parsers**: The Generation 3 save system uses a double-buffered architecture, splitting saves across two 56KB blocks (Block A at `0x0000` and Block B at `0xE000`) to prevent corruption. Since sections within these blocks are saved non-sequentially, parsers must read the `saveIndex` located at the end of each section (offset 4092) to determine the most recently written (valid) copy of the data.
*   **Gen 3 Berry Patches**: Each berry patch in Gen 3 is exactly 8 bytes long. The `stageByte` (byte 1) uses the lower 7 bits (`0x7f`) for the growth stage and the highest bit (`0x80`) as a flag to indicate if growth has stopped. The `wateredByte` (byte 5) tracks watering across all 4 growth stages in its upper 4 bits (`0x10`, `0x20`, `0x40`, `0x80`) and stores the total number of regrowths in its lower nibble (`0x0f`).
*   **Placeholder Functions**: The `isGen3Save` function is currently a placeholder designed to intentionally trigger a `RangeError` via bounds checking. This serves as scaffolding so the parent `parseSaveFile` function correctly delegates or falls back to Gen 1/2 handlers while full Gen 3 signature verification is still being built.

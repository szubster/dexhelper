# HexStreamOverlay Extraction

## What
Extracted a repeated JSX pattern across four components (`PokedexCard.tsx`, `SearchAndFilters.tsx`, `StorageGrid.tsx`, `SyncProgress.tsx`) representing a decorative hexadecimal data stream overlay.
Replaced raw `<div className="pointer-events-none absolute inset-0..."><div className="break-all font-mono...">{...}</div></div>` patterns with `<HexStreamOverlay>`.

## Why
Reduces duplicate JSX structures and centralizes the visual styling for the hexadecimal background data stream. Provides flexibility to either render a static string with a repeat count or generate randomized hexadecimal data streams with useMemo to avoid unexpected re-renders during React cycles.
Matches ADR 008 aesthetic requirements for "snooping / tactical hardware" interfaces.

## Key Learnings
- **React Performance**: When extracting components that generate random display data (like hex streams), wrapping the generation logic in `useMemo` and wrapping the component in `React.memo` is critical to prevent the component from re-generating new random numbers on every parent re-render, which could cause distracting visual flickering.
- **Diff Consistency**: When extracting a pattern that appears across multiple files, ensure the extracted component supports enough props (`textClassName`, `staticString`, `randomLength`, `repeat`) so that callers can match their original specific implementations (e.g., `text-[6px]` vs `text-[8px]`, or 10 repeats vs 20 repeats) without needing to add custom CSS beyond Tailwind utility classes.
- **In-place patch hygiene**: Pay close attention to patch failures, especially if editing deeply nested HTML structures in JSX. Replacing with git diff via `replace_with_git_merge_diff` is safer than raw `patch` for fixing minor spacing/padding regressions. Always remove `.orig` and `.rej` files before finalizing to avoid polluting the repo.

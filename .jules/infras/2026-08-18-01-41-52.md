## Critical Learnings
- **Tooling configuration context**: Discovered that Knip was running as part of the `pnpm lint` command but the `--reporter github-actions` was only defined in `.github/workflows/ci.yml`. More critically, Knip wasn't hooked into `lefthook.yml` pre-commits, meaning unused exports or dependencies could easily be committed by a local developer and only flagged once they hit GitHub Actions CI.
- **Action Taken**: Added `knip` to `lefthook.yml` under `pre-commit` hook (in parallel) to enforce unused export validation before code can be committed locally. Explicitly added `--no-exit-code` so developers receive warnings locally without being totally blocked from making local WIP commits, which balances local DX with codebase hygiene.
## Critical Learnings\n- **Build Optimization**: Replaced `@vitejs/plugin-react` with `@vitejs/plugin-react-swc`. The SWC-based plugin is significantly faster (written in Rust) compared to the Babel-based default, leading to reduced build times and faster Hot Module Replacement (HMR) during development. The `allowBuilds` constraint ensures we rely on pre-built native binaries rather than building from source.\n- **Tooling configuration context**: Discovered that `vitest.workspace.ts` was ignored by Knip. Removed it from `knip.json`'s ignore list, allowing Knip to natively analyze the workspace configuration.\n- **Interactive prompts in CI**: `pnpm approve-builds` triggers an interactive prompt for new build scripts. In headless environments, this can be bypassed by piping an empty string (`echo "" | pnpm approve-builds || true`), which safely defaults to denying the builds, aligning with our security posture.

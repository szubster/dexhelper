# Performance Optimization Journal

- **PalParkBatch Optimization**:
  - Pre-allocated a module-level static array `EMPTY_SLOT_INDICES` for the maximum batch size (6), replacing dynamic `Array.from({ length })` inside the render body. This eliminates intermediate iterator/array allocation overhead and garbage collection pressure when rendering repeated batch batches.
  - Wrapped `PalParkBatch` in `React.memo` to isolate component renders from parent tree updates.

- **PokedexGapVisualizerWidget Optimization**:
  - Replaced O(M * N) array linear search (`pokemonList.find()`) inside `Array.from(missingDex).map(...)` with an O(1) indexed Map lookup (`pokemonMap.get()`), memoized via `useMemo`. This transitions gap item computation complexity from O(M * N) to O(N + M), significantly reducing CPU cycles when calculating large gap sets against national Pokedex lists.
  - Wrapped `SimplePokedexGapVisualizer` and `PokedexGapVisualizerWidget` in `React.memo` to prevent redundant re-renders when parent dashboard states update without gap data changing.

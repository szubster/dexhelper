# Performance Optimization Journal - 2026-11-05

## Algorithmic & Complexity Learnings: Set Lookups vs Linear Scans in Nested Save Iteration
- In `src/engine/assistant/generators/synergyDataGenerator.ts`, multi-save synergy data aggregation iterates through pairs of save files and checks whether each missing Pokémon is a game exclusive for the target save.
- Previously, `getGameExclusives(save).missing` returned an array (`number[]`). Inside the nested double loop over saves and owned Pokémon (`for (const pokemonId of sourceSave.owned)`), checking `missingExclusives.includes(pokemonId)` caused an $O(N \times M)$ scan for each candidate Pokémon against the missing exclusives list.
- Precomputed `targetExclusivesMap` as `Record<string, Set<number>>` upfront, transitioning inner lookup complexity from $O(N \times M)$ to $O(1)$ amortized `Set.has()` checks. This eliminated repetitive array scanning across hundreds of Pokémon entries during multi-game synergy calculations.

## React Rendering Isolation: DagTreeItem Memoization
- With the transition from `@xyflow/react` to custom DAG directory tree components (`DagTree` / `DagTreeItem`), DAG nodes are rendered hierarchically.
- Wrapped `DagTreeItem` in `React.memo` to eliminate cascading re-evaluations across entire DAG subtrees when unrelated filter parameters or context values update without individual node props changing.

# Nurse Joy Journal Entry

**Timestamp:** 2026-10-09-03-23-49
**Target:** Safe generic parameterization for `<ReactFlow>` event handlers in `src/components/dag/DagDashboard.tsx`
**Issue:** `onNodesChange` and `onEdgesChange` props on `<ReactFlow>` were using unsafe `as any` type assertions along with `biome-ignore lint/suspicious/noExplicitAny` comments because `<ReactFlow>` defaulted its generic parameters to base `Node` types rather than the custom `DagNode` and `DagEdge` types provided by `DagContext`.
**Solution:** Explicitly passed generics `<ReactFlow<DagNode, DagEdge>>` to `<ReactFlow>`, allowing TypeScript to cleanly infer `OnNodesChange<DagNode>` and `OnEdgesChange<DagEdge>` handlers without any `as any` casts.
**Key Takeaway:** When third-party React components (like `@xyflow/react` `<ReactFlow>`) accept custom node or edge data structures, explicitly parameterizing the component generics (`<ReactFlow<NodeT, EdgeT>>`) resolves prop type mismatches at the call site, eliminating the need for `as any` assertions or linter suppressions.

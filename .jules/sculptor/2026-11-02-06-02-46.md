# Sculptor Journal - 2026-11-02-06-02-46

## Refactoring Goal
Improve AI readability and domain modeling in `src/engine/gen3/lottery/lottery.ts` by replacing inline magic numbers and nested conditional checks with explicit named constants, strong union typing (`LotteryTier`), and a declarative match-count-to-tier lookup dictionary (`MATCH_COUNT_TO_TIER`).

## Critical Learnings
- **Inline integers obscure domain semantics:** Using raw numbers (`0 | 1 | 2 | 3 | 4`, `5`, `0`) for lottery tiers and match limits obscures the domain meaning (e.g., Tier 1 = Grand Prize 5 digits match, Tier 4 = Fourth Prize 2 digits match, Tier 0 = No Match).
- **Declarative Lookup Tables Eliminate Multi-Branch Decision Chains:** The repeated `if (matches === 5) return 1; ...` construct introduces imperative branching that is redundant. Replacing it with `MATCH_COUNT_TO_TIER[matches] ?? LOTTERY_TIER_NO_MATCH` makes the logic declarative, concise, and immediately predictable for LLMs and AI agents reading the codebase.
- **Explicit Comparison Semantics:** Replacing checks like `tier !== 0` with `tier !== LOTTERY_TIER_NO_MATCH` and `bestTier === 1` with `bestTier === LOTTERY_TIER_FIRST_PRIZE` clarifies the algorithmic intent (that lower tier numbers represent better prizes) without requiring the AI to deduce this from inline comments.

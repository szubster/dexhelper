# Sculptor Journal - 2026-11-09

## Refactoring Goal
Improve AI readability and predictable control flow in `src/engine/filtering/EVFilters.ts` by replacing multi-branch `switch` statements with declarative lookup dictionaries (`EV_STAT_EXTRACTORS`, `EV_OPERATORS`) and pure, single-purpose helper functions (`calculateTotalEVs`, `isEVTotalStat`).

## Actions Taken
- Extracted `EV_STAT_EXTRACTORS` lookup map connecting individual `EVStat` names to their corresponding `PokemonInstance['evs']` property accessors.
- Extracted pure helper `calculateTotalEVs` for computing sum of all EV stats without embedding inline arithmetic inside `switch` cases.
- Added type guard `isEVTotalStat` to separate aggregate stat calculation from individual property extraction.
- Replaced imperative `switch (operator)` in `evaluateEVOperator` with declarative `EV_OPERATORS` lookup record.
- Added unit tests in `src/engine/filtering/EVFilters.test.ts` to verify `calculateTotalEVs` and `isEVTotalStat`.

## Critical Learnings
- **Declarative Lookup Dictionaries Prevent Nested Switch Creep:** When evaluating domain stats or filtering operators, using `switch-case` constructs invites cognitive bloat for LLMs. Declarative lookup dictionaries create self-documenting mapping tables that are trivial for AI agents to parse, extend, or type-check without parsing branching control flows.
- **Dedicated Aggregate Helpers Decouple Special-Case Logic:** Stat enumerations often mix single attributes (like `attack`, `defense`) with aggregate calculations (like `total`). Extracting dedicated aggregation helpers like `calculateTotalEVs` ensures that single attribute accessors remain uniform functions, making the logic predictable and straightforward.

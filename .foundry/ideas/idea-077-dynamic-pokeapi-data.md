# Idea: Parse items and moveset PPs from repository data during build

## Context
Currently, memory offsets, base move PPs, and authoritative item lists are manually compiled in `RESEARCH` nodes or hardcoded. These lists can be long and maintenance-heavy. We can parse the existing repository data to dynamically generate move parameters and item lists during the build process, similar to how `encounters.jsonl` is handled.

## Proposal
- During build time, parse required data (e.g., move PPs, valid items) directly from the existing repository data instead of fetching from an external API.
- Store this data in `.jsonl` files (e.g. `items.jsonl`, `moves.jsonl`) generated by build scripts like `scripts/generate-pokedata.ts`. The vite plugin will package this for client access, mirroring the pattern used for encounters.
- Reduce hardcoded tables in the codebase, ensuring data remains authoritative without manual updates.

## Benefits
- Removes large static data tables from the repository.
- Improves scalability for future generations of Pokémon data.

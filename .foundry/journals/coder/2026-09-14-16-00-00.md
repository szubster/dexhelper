# Gen 3 Pokeblocks Implementation

## Learnings
When filtering items or iterating over an array from the save file (such as Gen 3 Pokéblocks), be sure to handle empty slots (often represented by a `color` or `id` of `0`). It is acceptable to gracefully render empty or filter out these empty items to keep the dashboard clean. Also, remember that `isGen3Save` in `detection.ts` is explicitly stubbed and shouldn't be relied on for strict testing during development since Gen 3 uses structural fallback detection via A/B flash banks.

## UI Components
Ensure that when using `map` to render lists of items extracted from a save block without inherent unique IDs, it is permissible to cautiously use the array index as a key (e.g. `key={i}`) provided the list is statically read-only. However, `biome` linting will reject plain array indices (`key={i}`). You must format it with a string prefix (e.g., `key={\`pokeblock-${i}\`}`) and use the exact biome ignore comment `// biome-ignore lint/suspicious/noArrayIndexKey:` accompanied by a valid explanatory intent string describing why the index is safe (e.g., "List is read-only and static"). Failure to include the explanation string causes Biome to reject the suppression comment.

## Playwright Assertions
When verifying visibility, `expect(page.getByText('POKÉBLOCKS')).toBeVisible()` will inherently verify that the parent section successfully loaded and the UI did not crash from the extracted data payload.

# Coder Journal

## Session Insights
When manually parsing git diff outputs to identify file paths (e.g., in CI analysis scripts like `analyze-diff.js`), it's significantly more robust to parse the `diff --git a/... b/...` lines using regex to extract filenames rather than relying on `+++` or `---` lines. New files and deleted files have `/dev/null` in either the `+++` or `---` line, which leads to path extraction failures if not handled explicitly. Extracting both paths from the main `diff --git` line ensures we capture the target file path regardless of whether the file was added, modified, or removed.

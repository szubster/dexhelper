# False Permanent Failures via Max Rejections
When a child task reaches its maximum rejection count due purely to repeated behavioral policy violations (such as the autonomous No-Ask policy violation) rather than an actual technical defect, the failure is a "false permanent failure".

To resolve this impossible loop, the standard protocol must still be followed:
1. Spawn a `RESEARCH` node to verify the root cause.
2. Spawn replacement implementation and QA `TASK` nodes depending on the research.
3. Explicitly check off (`- [x]`) the permanently failed child nodes in the parent's markdown body.
4. Append the new replacement nodes as unchecked checkboxes (`- [ ]`).

This ensures the parent node is unblocked and the implementation can proceed without abandoning the story.

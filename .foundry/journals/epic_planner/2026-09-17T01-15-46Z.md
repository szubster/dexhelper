# Journal Entry - Agent Confidence Metrics Schema Strictness

When decomposing `prd-521-565-agent-confidence-metrics-dashboard` into child Epics, two critical DAG ID schema rules were reinforced:

1. **Parent-Linked ID Schema**: When a parent PRD ID is `<type>-<epic_planner_epic>-<parent_NNN>-<slug>` (e.g. `prd-521-565`), the generated children MUST drop the first NNN and use the `<parent_NNN>` as their prefix (e.g., `epic-565-<new_NNN>`). I initially used the root `521` instead of `565`, which violates the hierarchy.
2. **DAG ID Strictness**: When setting the `depends_on` array, the values MUST strictly be exact Node IDs without file extensions (e.g., `epic-565-569-agent-confidence-metrics-schema`), rather than repository-relative file paths (like `.foundry/epics/...`). Using file paths breaks the orchestrator's dependency resolution logic.

Moving forward, I will strictly enforce the ID schema extraction and ensure exact Node IDs are used for all `depends_on` mappings.

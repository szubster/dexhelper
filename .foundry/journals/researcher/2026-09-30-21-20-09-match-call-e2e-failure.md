# Root Cause Analysis: task-473-493-gen3-match-call-e2e-impl Failure

## Description
Investigated the permanent failure (`Max rejection count reached`) of `task-473-493-gen3-match-call-e2e-impl`.

## Findings
The task was responsible for implementing E2E tests validating the Gen 3 Match Call extraction against standard Gen 3 saves using Playwright.
Upon inspecting the repository state and the Coder's journal, the following issues were identified:
1. **Confusion with Static Data:** The repository contains an E2E test file (`tests/e2e/gen3_match_call_static_data.spec.ts`), but this tests the static MSGPack database data (`match_calls` IndexedDB store) generated by the `pokedata-plugin`, rather than testing the dynamic extraction of `gen3MatchCall` state from a save file.
2. **Missing E2E Implementation:** The Coder noted in their journal: "- Successfully verified match call integration inside the parser testing suites". This indicates the Coder mistakenly believed that writing unit tests (in `src/engine/saveParser/parsers/gen3.test.ts`) satisfied the E2E testing requirement, leading to a failure to implement actual Playwright E2E tests for the save extraction.
3. **Application State Integration:** The parsed `gen3MatchCall` data is actually surfaced in the application via Assistant suggestions (in `src/engine/assistant/strategies/utils/matchCall.ts`), which creates a `Match Call Rematches` suggestion when rematches are available.

## Guidelines for New Implementation (task-473-599)
- Do not modify `tests/e2e/gen3_match_call_static_data.spec.ts`. That is a separate feature.
- Create a new Playwright test file (e.g., `tests/e2e/gen3_match_call_save_extraction.spec.ts`).
- The test must use `initializeWithSave` (using `tests/fixtures/emerald.sav`).
- Verify the extraction by asserting that the application UI renders the resulting Assistant suggestion: `Match Call Rematches`.

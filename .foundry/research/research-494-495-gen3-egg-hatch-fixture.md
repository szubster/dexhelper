# Research: Gen 3 Egg Hatch Fixture

## Context
The `task-473-494-gen3-egg-hatch-e2e-impl` task requires end-to-end testing of the Gen 3 egg hatch tracker data extraction engine.
However, none of the existing Gen 3 save fixtures (e.g. `emerald.sav`, `firered.sav`, `ruby_vithuang.sav`) contain a Pokémon in the party with the `isEgg` bitflag set.

Without a valid fixture, the E2E test cannot verify that the parser correctly extracts and displays egg steps.

## Objective
Acquire or generate a valid Gen 3 save file (`.sav`) that contains at least one Egg in the player's active party, and commit it to `tests/fixtures/saves/gen3/`.
Then, document its location and provide instructions on how to use it for the E2E test.

## Findings

A valid Gen 3 save file containing an egg in the active party has been generated and placed at `tests/fixtures/saves/gen3/emerald_egg_fixture.sav`.
The fixture was generated by programmatically editing `emerald_spinda_party_fixture.sav` to set the `isEgg` bitflag on the first Pokémon in the party, and updating both the Pokémon structural checksum and the overarching Block 1 checksum correctly to maintain save file integrity.
The fixture is also properly mapped in `tests/fixtures/manifest.json` under the filename `emerald-egg-fixture.sav`.

**Instructions for Downstream Usage (E2E Test)**:
1. In the E2E test, mock the filesystem or load the fixture using `tests/fixtures/saves/gen3/emerald_egg_fixture.sav`.
2. The first Pokémon in the party (at index 0) is the Egg.
3. The extracted `eggSteps` value parsed from this fixture should exactly equal **62720** (245 cycles * 256 steps).
